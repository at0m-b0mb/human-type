Desktop app · macOS · Windows · Linux

Types text the way a person would.

Some windows will not take a paste — kiosk forms, remote consoles, legacy apps, demo recordings where a wall of text appearing at once looks wrong. Human Typer types it in instead, with drifting rhythm, per-key effort, and mistakes noticed a beat late rather than instantly.

View on GitHub python human-type.py

The text that lands in the other window is byte-identical to the text you gave it.

The engine invents typos, transpositions and missed shifts, then notices each one a few characters later, backspaces and retypes it — because that is what people do. The realism lives in the timing and the keystrokes, never in the finished document.

A property test replays every event stream across every profile, every seed and an adversarial corpus, and asserts the result reconstructs the input exactly. A second proves a correction can never backspace across a line break, which in a chat box would send a half-written message.

This makes typing look human. It does not make writing look human-written, and it has no mode that does.

What makes it look human

Most typing simulators pick a delay and add random jitter. That is the one thing real typing never does — the jitter is independent from key to key, which reads as a machine adding noise.

01

Rhythm that drifts

Speed wanders in runs lasting seconds, not per keystroke — a mean-reverting walk in log space, so cadence has texture and still returns to your set pace. The tests check its autocorrelation is above 0.5: a rhythm, not noise.

02

Keys that cost different amounts

A pinky reach to p is slower than a. A question mark costs a shift. The largest real effect is the same finger twice in a row — de, un, ol — and the largest saving is alternating hands.

03

Mistakes noticed late

Every other simulator catches its typo on the very next keystroke. Nobody does that. Here a slip runs on for one to eight more characters before your eyes catch up — the clearest tell between a person and a script, and it is a slider.

04

Warm-up, fatigue and thinking

The first lines come out cold. Long documents slow down. Bursts of a few words are followed by a breath, and a new sentence sometimes waits while you compose it.

Open a document, type it somewhere else

Only the words come across. A keyboard produces characters, so bold, headings, tables, images and fonts have no keystroke equivalent and are left behind.

FormatNotes
.txt .md .csv .jsonRead directly, with encoding fallback
.docxWord. Paragraph breaks kept; tracked deletions are not imported
.odtOpenDocument and LibreOffice
.rtfControl words and font tables stripped
.htmlTags stripped, block elements become paragraphs
.pdfOnly when pypdf is installed

Everything but PDF is read with the Python standard library, so opening a Word document adds no dependency. Archive members are size-capped before extraction, so a hostile file cannot exhaust memory.

Get started

Python 3.9 or newer.

git clone https://github.com/at0m-b0mb/human-type

pip install -r requirements.txt

python human-type.py

F5 starts · F6 pauses and resumes · Esc stops. Moving the mouse to the top-left corner of the screen aborts immediately, at any moment.

On macOS, grant Accessibility permission to whatever launches the app, or no keystrokes are sent at all.
